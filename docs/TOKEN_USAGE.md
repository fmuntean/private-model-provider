# Token Usage Guide

Understanding token usage is essential for managing costs and staying within model limits.

## What Is a Token?
A token roughly corresponds to a word or a piece of punctuation. Most LLM APIs return a `usage` object with three fields:
- `prompt_tokens` – tokens sent to the model (including the system prompt and user messages).
- `completion_tokens` – tokens generated by the model.
- `total_tokens` – sum of the above.

## How the Extension Tracks Tokens
1. **Provider Response** – `provider.ts` extracts the `usage` object from the API response.
2. **Statistics Module** – `statistics.ts` adds the numbers to a per‑session accumulator and persists a cumulative total in the extension’s global state.
3. **Status Bar** – `statusBar.ts` reads the cumulative total and displays it as `🪙 1234 tokens`.
4. **Export** – Users can export the current session’s stats via the **Export** button in the chat UI.

## Viewing Token Stats
- **In‑Chat** – The bottom of the chat pane shows `Tokens used this session: X` after each response.
- **Status Bar** – A badge on the right side of the VS Code status bar shows the overall token count for the current VS Code session.
- **Command Palette** – Run **Local Model Provider: Show Token Stats** to open a quick‑pick view with detailed numbers (session, daily, total).

## Managing Limits
- **Max Tokens Setting** – `localModelProvider.maxTokens` caps the number of tokens the model may generate per response.
- **Warning Threshold** – When the cumulative total exceeds 90 % of the user‑defined `maxDailyTokens` (if set), the extension shows a warning dialog.
- **Reset** – Use **Clear Chat** to reset the session counter; the global total persists across sessions unless the user manually clears it via the **Reset Stats** command.


---
*Token tracking is optional – disable it by setting `localModelProvider.showTokenStats` to `false`."
